* Por que simular?

- Simulação é uma das três técnicas de avaliação de desempenho
  - Modelagem analítica, *simulação* e medição
- Útil quando
  - O sistema real não está disponível (ainda em projeto, caro demais)
  - Muitas cargas/ambientes/alternativas precisam ser testados
  - O modelo analítico exige hipóteses irrealistas

#+latex: \vfill\pause

- Apesar da utilidade, muitos projetos de simulação fracassam
  - Ou produzem resultados enganosos
  - Desequilíbrio frequente: boa engenharia de software e estatística
    fraca (ou o contrário)
  - Simulações grandes demoram muito mais do que o previsto

* Erros comuns (1/3)

** Nível de detalhe inadequado                                     :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
- Mais detalhe \Rightarrow mais tempo de desenvolvimento, mais bugs, execução mais lenta
- Modelo detalhado exige dados de entrada detalhados
  - Ex.: disco -- tempo de serviço exponencial vs. simular cabeça e rotação
    sem conhecer os setores acessados (gera setores aleatórios\dots)
- *Comece simples*, analise a sensibilidade, refine só onde importa

#+latex: \vfill\pause

** Linguagem inadequada                                            :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
- Linguagens/bibliotecas de simulação: desenvolvimento rápido, trace e
  estatísticas prontos
- Linguagens de propósito geral: portabilidade e controle de desempenho
- Hoje: núcleo compilado (rápido) + API em linguagem de script (ex.: SimGrid)

* Erros comuns (2/3)

** Modelos não verificados e inválidos                             :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
- Bugs tornam as conclusões sem sentido
- Código correto pode ser inválido: hipóteses erradas sobre o sistema
- Desconfie dos resultados até que sejam confrontados com teoria,
  medições e intuição de especialistas

#+latex: \vfill\pause

** Simulações curtas demais                                        :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
- Resultados dominados pelas *condições iniciais* (não pelo regime permanente)
- O comprimento necessário depende da precisão desejada e da variância da métrica
- Estatística ``ingênua'' falha: observações *autocorrelacionadas*
  - Remoção do aquecimento + médias em lotes (\textit{batching}) + observação
    suficientemente longa

* Erros comuns (3/3)

** Geradores aleatórios ruins                                      :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
- Geradores caseiros/fracos introduzem viés
- Use geradores testados de bibliotecas confiáveis (o padrão do R é o
  Mersenne-Twister)

#+latex: \vfill\pause

** Escolha inadequada de sementes                                  :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
- Reusar sementes entre réplicas \Rightarrow fluxos correlacionados
  (ou idênticos!)
- Sementes distintas para cada réplica / fluxo; *registre-as* para
  reprodutibilidade (=set.seed()=)

* Terminologia

- *Variáveis de estado* (definem o estado) e *eventos* (mudam o estado)

#+latex: \vfill\pause

- Tempo contínuo vs. tempo discreto
  - Estado definido em todo instante vs. só em instantes específicos
- Estado contínuo vs. estado discreto
  - Ex.: tempo gasto estudando vs. nº de jobs na fila da CPU
  - Modelos de estado discreto = *modelos de eventos discretos*
  - Continuidade do tempo não implica continuidade do estado (4 combinações)

#+latex: \vfill\pause

- Determinístico vs. probabilístico
  - Mesma entrada \Rightarrow mesma saída vs. saídas diferentes
- Estático vs. dinâmico
  - O tempo não aparece vs. o estado evolui com o tempo
- Linear vs. não linear
- Aberto vs. fechado
  - Entrada externa independente vs. jobs circulam dentro do sistema

* Estrutura de um simulador de eventos discretos (1/2)

Todo DES compartilha uma arquitetura comum

#+latex: \vfill

** Escalonador de eventos                                          :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
- Mantém a *lista de eventos* futuros, ordenada por tempo
- Operações: agendar evento X no tempo T; adiar X por \(\Delta t\);
  cancelar; suspender indefinidamente; reativar
- É o componente executado com mais frequência (antes de cada evento)
  - Estrutura de dados importa: lista ligada, \textit{heap}, \textit{calendar queue}

#+latex: \vfill\pause

** Relógio da simulação e avanço do tempo                          :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
- Variável global com o tempo *simulado* (\(\neq\) tempo de parede!)
- Avanço por *unidade de tempo*: incrementa \(\Delta t\) e verifica se há eventos
- Avanço *dirigido por eventos*: salta direto para o próximo evento
  - Padrão em simulação de sistemas computacionais

* Estrutura de um simulador de eventos discretos (2/2)

- *Inicialização*: estado inicial do sistema; sementes/fluxos aleatórios
- *Variáveis de estado*: nº de jobs na fila, nº de fluxos num enlace, \dots
- *Rotinas de evento*: uma por tipo de evento (chegada, partida, \dots)
  - Atualizam o estado e agendam novos eventos
- *Gerador de relatório*: calcula e imprime os resultados ao final
- *Rotinas de trace*: imprimem variáveis intermediárias
  - Essenciais para depurar; desligáveis em produção
- *Programa principal*: lê entradas, inicializa, itera, gera relatório

#+latex: \vfill\pause

** Laço principal (pseudocódigo)                                   :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
#+begin_src text :exports code
inicializa(estado, relógio = 0, lista_eventos, sementes)
enquanto (não terminou):
    ev      <- remove_próximo(lista_eventos)     # escalonador
    relógio <- ev.tempo                          # avança o relógio
    rotina[ev.tipo](estado, lista_eventos)       # atualiza estado, agenda eventos
    se (trace): imprime(relógio, ev, estado)
relatório(estatísticas)
#+end_src

* Exemplo: fila de servidor único (M/M/1)

#+begin_center
chegadas \(\xrightarrow{\ \lambda\ }\) [ fila FIFO | servidor ] \(\xrightarrow{\ \mu\ }\) partidas
#+end_center

- Intervalos entre chegadas \(\sim \mathrm{Exp}(\lambda)\); tempos de serviço \(\sim \mathrm{Exp}(\mu)\)
- *Estado*: \(N\) = nº de clientes no sistema (fila + servidor)
- *Eventos*: chegada e partida

#+latex: \vfill\pause

** Rotinas de evento                                               :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
- *Chegada*: \(N \leftarrow N+1\); agenda próxima chegada em
  \(t + \mathrm{Exp}(\lambda)\); se o servidor estava livre (\(N=1\)),
  agenda partida em \(t + \mathrm{Exp}(\mu)\)
- *Partida*: \(N \leftarrow N-1\); registra o tempo de resposta do cliente; se
  \(N>0\), agenda a próxima partida, senão partida \(=\infty\)

#+latex: \vfill\pause

** Resultados teóricos (regime permanente, \(\rho < 1\))           :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
\[
\rho = \frac{\lambda}{\mu}, \qquad
\mathbb{E}[N] = \frac{\rho}{1-\rho}, \qquad
\mathbb{E}[T] = \frac{1}{\mu-\lambda} \quad (\text{Lei de Little: } \mathbb{E}[N] = \lambda\, \mathbb{E}[T])
\]

#+begin_src R :exports code
mm1_sim <- function(lambda, mu, n_clientes, semente = NULL, trace = FALSE) {
  if (!is.null(semente)) set.seed(semente)       # inicialização: gerador
  relogio <- 0                                    # relógio da simulação
  fila    <- numeric(0)   # estado: instantes de chegada de quem está no sistema
  prox    <- c(chegada = rexp(1, lambda),         # lista de eventos:
               partida = Inf)                     #   servidor vazio
  area_N  <- 0            # integral de N(t) dt (para o N médio)
  inicio  <- 0            # início do serviço do cliente na frente da fila
  r_cheg <- r_ini <- r_part <- numeric(n_clientes) # saída (pré-alocada)
  k <- 0                                          # nº de partidas
  ...
#+end_src

#+latex: \vfill

- Só dois tipos de evento \Rightarrow a ``lista de eventos'' é um vetor nomeado
  com o próximo instante de cada tipo; o escalonador é =which.min()=
- Em simuladores gerais: fila de prioridade (\textit{heap}) de eventos
- \(N\) = =length(fila)=; guardamos os instantes de chegada para calcular
  o tempo de resposta na partida

* Prática: =a26_mm1.R= -- laço principal e rotinas de evento

#+begin_src R :exports code
  while (k < n_clientes) {
    ev <- names(which.min(prox))                  # escalonador: próximo evento
    area_N  <- area_N + length(fila) * (prox[[ev]] - relogio)
    relogio <- prox[[ev]]                         # avança o relógio
    if (ev == "chegada") {                        # --- rotina de chegada
      fila <- c(fila, relogio)                    # entra no sistema
      prox["chegada"] <- relogio + rexp(1, lambda)
      if (length(fila) == 1) {                    # servidor estava livre
        inicio <- relogio; prox["partida"] <- relogio + rexp(1, mu) }
    } else {                                      # --- rotina de partida
      k <- k + 1
      r_cheg[k] <- fila[1]; r_ini[k] <- inicio; r_part[k] <- relogio
      fila <- fila[-1]                            # sai do sistema (FIFO)
      if (length(fila) > 0) { inicio <- relogio; prox["partida"] <- relogio + rexp(1, mu) }
      else prox["partida"] <- Inf }
  }
#+end_src

- Ao final (relatório): =data.frame= com =chegada=, =inicio=, =partida=,
  =resposta= de cada cliente e o atributo =N_medio= \(= \texttt{area\_N}/\texttt{relogio}\)

# IC t-Student para a média de um vetor de observações (supostamente independentes)
ic <- function(x, conf = 0.95) {
  n <- length(x); m <- mean(x); h <- qt(1 - (1 - conf)/2, n - 1) * sd(x) / sqrt(n)
  c(media = m, inf = m - h, sup = m + h)
}

#+latex: \begin{center}
*Verificação*: o programa implementa corretamente o modelo? (depuração)

#+latex: \vfill\pause

** Técnicas de verificação                                         :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
#+latex: \begin{columns}[T]\begin{column}{.48\linewidth}
- Projeto modular \textit{top-down}
- \textit{Antibugging}: checagens de consistência no código
  (ex.: \(N \geq 0\), nº de chegadas \(=\) partidas \(+ N\))
- Revisão estruturada (\textit{walk-through})
- Modelos determinísticos (resultado conhecido)
- Casos simplificados (1 cliente, só chegadas)
- \textit{Trace} e visualização \textit{on-line}
#+latex: \end{column}\begin{column}{.48\linewidth}
- Teste de *continuidade*: pequena mudança na entrada \(\Rightarrow\) pequena
  mudança na saída
- Teste de *degenerescência*: valores extremos (\(\lambda \to 0\), \(\rho \to 1\))
- Teste de *consistência*: cenários equivalentes dão o mesmo resultado
  (ex.: 2 servidores de vel. 1 vs. 1 de vel. 2 com carga leve)
- *Independência da semente*: resultados não podem depender da semente
#+latex: \end{column}\end{columns}

#+latex: \vfill\pause

- E, quando existe: *comparar com a teoria* (nosso caso: M/M/1)

* Verificação contra a teoria: experimento

- \(\mu = 1\); \(\rho \in \{0{,}5;\ 0{,}8;\ 0{,}9\}\)
- \(m=10\) réplicas independentes (sementes distintas), \(22.000\) clientes cada
- Descartamos os 2.000 primeiros clientes (aquecimento, ver adiante)
- Média de cada réplica \(\Rightarrow\) IC 95% (t de Student, 9 g.l.)

* Regime transiente: o problema

* Remoção do transiente (Jain, cap. 25)

Em geral não se sabe onde o transiente termina \Rightarrow métodos heurísticos

#+latex: \vfill

1. *Execuções longas*: o transiente fica diluído (desperdício, sem garantia)
2. *Inicialização adequada*: começar num estado próximo do permanente
3. *Truncamento*: descartar até a observação \(l\) deixar de ser o mín./máx.
   do restante
4. *Remoção de dados iniciais*: descartar \(l\) observações e ver se a média
   do restante muda
5. *Média móvel de réplicas independentes* (método de Welch)
6. *Médias em lotes*: ver se a média do 1º lote destoa das demais

#+latex: \vfill\pause

** Método de Welch (média móvel de réplicas)                       :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
1. Faça \(m\) réplicas de comprimento \(n\); calcule a média *entre réplicas*
   de cada observação: \(\bar x_j = \frac{1}{m}\sum_{i=1}^m x_{ij}\)
2. Suavize \(\bar x_j\) com uma média móvel de janela \(2w+1\)
3. Escolha \(l\) onde a curva suavizada se estabiliza (inspeção visual);
   aumente \(w\) se ainda estiver ruidosa

* Remoção do transiente: método de Welch na prática

#+attr_latex: :width .9\linewidth
[[file:pdf_babel/a26_welch.pdf]]

- \(\rho=0{,}9\), \(m=200\) réplicas de 3.000 clientes, janelas \(w=10\) e \(w=100\)
- A curva suavizada atinge o patamar \(\approx 10\) em torno de
  \(l \approx 300\)--500 clientes; depois só oscila em torno de 10
- Por segurança, descartamos \(l = 2.000\) (custo pequeno frente a 20.000
  observações úteis por réplica)
- Poucas réplicas \Rightarrow curva ruidosa: aumente \(m\) ou \(w\)

## Método de Welch: média entre m réplicas de cada observação + média móvel

X <- sapply(1:m, function(i) mm1_sim(0.9, 1, n, semente = 200 + i)$resposta)  # n x m

  geom_line() +
  geom_hline(yintercept = 10, linetype = "dashed") +

* Simulações terminais vs. de regime permanente

- *Regime permanente*: interessa o comportamento ``para sempre''
  (servidor web operando continuamente) \Rightarrow remover transiente
- *Terminais*: o próprio transiente é o objeto de estudo
  - Sistema que é desligado/reiniciado; janela de tempo fixa
    (ex.: expediente de um banco; execução de um job/aplicação paralela)
  - *Não* se remove o transiente; o estado inicial faz parte do modelo
  - Réplicas independentes com as mesmas condições iniciais

- Ao parar no tempo \(t_{\max}\), clientes ainda no sistema não têm tempo de
  resposta \Rightarrow incluí-los ou não introduz viés
- Médias no tempo (ex.: \(\bar N\)) vs. médias por cliente (ex.: \(\bar T\)):

* Critério de parada: quão longa deve ser a simulação?

- Rodar até que o IC da média tenha a largura desejada
  - Ex.: \(\bar T \pm 5\%\) com 95% de confiança
- Precisamos da *variância da média* \(\mathrm{Var}(\bar x)\)

#+latex: \vfill\pause

** A armadilha: observações autocorrelacionadas                  :B_block:
:PROPERTIES:
:BEAMER_env: block
:END:
- IC ``ingênuo'': \(\bar x \pm t_{1-\alpha/2;\,n-1}\, s/\sqrt{n}\) supõe
  observações *independentes*
- Com correlação positiva, \(\mathrm{Var}(\bar x) \gg s^2/n\)
  \[ \mathrm{Var}(\bar x) = \frac{\sigma^2}{n}\Big[1 + 2\sum_{k=1}^{n-1}\Big(1-\frac{k}{n}\Big)\rho_k\Big] \]
  \Rightarrow IC ingênuo *estreito demais*: falsa precisão!

:BEAMER_env: block
:END:
1. Réplicas independentes
2. Médias em lotes (\textit{batch means})
3. Método da regeneração

* Solução 1: réplicas independentes

- \(m\) réplicas, cada uma com sementes distintas, comprimento \(n_0 + n\)
- Descarta as \(n_0\) primeiras observações de cada réplica

\[
\bar x_i = \frac{1}{n}\sum_{j=n_0+1}^{n_0+n} x_{ij}, \qquad
\bar{\bar x} = \frac{1}{m}\sum_{i=1}^{m} \bar x_i, \qquad
s^2 = \frac{1}{m-1}\sum_{i=1}^{m} (\bar x_i - \bar{\bar x})^2
\]
\[
\text{IC: } \bar{\bar x} \pm t_{1-\alpha/2;\,m-1}\, \frac{s}{\sqrt m}
\]

#+latex: \vfill\pause

#+begin_src R :exports code
medias <- sapply(1:10, function(i) {
  d <- mm1_sim(lambda = 0.8, mu = 1, n_clientes = 22000, semente = 8000 + i)
  mean(d$resposta[-(1:2000)])           # descarta o aquecimento
})
t.test(medias)$conf.int                 # IC 95% entre réplicas
#+end_src

#+latex: \vfill\pause

- \(+\) Médias das réplicas são de fato independentes (sementes distintas)
- \(-\) Cada réplica paga o custo do aquecimento (\(m \cdot n_0\) observações descartadas)
- Natural para simulações *terminais*

* Solução 2: médias em lotes (\textit{batch means})

- *Uma* execução longa; descarta \(n_0\); divide o restante em \(m\) lotes
  contíguos de tamanho \(n\)
- Média de cada lote \(\bar x_i\) \(\to\) mesmas fórmulas das réplicas
- Escolha de \(n\): aumentar até a correlação entre lotes consecutivos ser
  desprezível (figura anterior)

#+latex: \vfill\pause

#+begin_src R :exports code
d <- mm1_sim(lambda = 0.8, mu = 1, n_clientes = 21000, semente = 5001)
x <- d$resposta[-(1:1000)]               # descarta o aquecimento
lotes <- colMeans(matrix(x, ncol = 20))  # 20 lotes de 1000 clientes
t.test(lotes)$conf.int                   # IC 95% com médias de lotes
t.test(x)$conf.int                       # IC "ingênuo": NÃO FAÇA ISSO
#+end_src

#+latex: \vfill\pause

- \(+\) Paga o aquecimento só uma vez
- \(-\) Lotes adjacentes ainda um pouco correlacionados se \(n\) for pequeno
- *Regeneração*: lotes delimitados por instantes em que o sistema ``renasce''
  (ex.: fila esvazia) \Rightarrow ciclos independentes, mas de tamanho variável
  (estimador de razão)
